# F5 기술 검토

간단한 사용법 질문은 명령, 입력 위치, 확인된 버전을 먼저 답한다. “지원하나요?”라는 질문에서는 문서가 보장하는 범위와 실제 환경에서의 관찰을 각각 확인한다. 고객 회신, RFP 답변, 시험 보고서 등 사용자가 요청한 형식으로 마무리한다.

## 근거 찾기

1. 제품·모듈, 릴리스, 사용자가 확인하려는 동작을 식별한다. 문서가 말하는 기능 추가 버전과 시험한 장비 버전을 따로 기록한다.
2. 연결된 `f5-reference`의 `search_sources`로 Bug ID 또는 명령을 검색하고, 관련 결과의 ID를 `read_source`에 전달한다. `search_approved`에서 비슷한 회신을 찾으면 당시 버전과 근거를 대조한다. 출처 목록만 요청한 경우에는 `list_sources`로 충분하다.
3. 사용자가 준 공식 문서는 직접 열어 해당 절을 읽는다. 로컬 검색이 비거나 본문이 없는 경우에도 문서 번호, 제품과 릴리스로 F5 공식 원문을 확인한다. 확인한 문서의 제목·절·링크를 해당 주장에 붙인다. MCP나 웹 검색을 사용할 수 없으면 확인 가능한 근거 범위를 밝힌다.

## 문서와 시험 결과 대조

- 공식 문서의 기능 설명, 사용자 제공 시험 요약, 직접 열어 확인한 캡처·로그를 구별한다. 자료에 없는 장비 빌드, 응답 코드, 분류 문자열을 보충하지 않는다.
- 판정 대상마다 질문을 나눈다. 예를 들어 “SNI가 추출됐는가?”에는 패킷의 이름과 PEM 로그가, “서비스가 응답했는가?”에는 핸드셰이크·응답 관찰이 필요하다. 한쪽 결과로 다른 쪽의 성공을 추정하지 않는다.
- 제품명과 명령이 일치하더라도 규격 세대·버전·프로파일이 달라지면 같은 근거를 그대로 적용할 수 있는지 확인한다. 공식 문서가 프로토콜 세대를 구분하지 않는다면 그 범위를 명시한다.
- 결론은 ‘문서에 명시됨’, ‘이 환경에서 관찰됨’, ‘추가 확인 필요’ 중 해당하는 근거와 함께 쓴다. 자료가 엇갈리면 공통으로 확인되는 부분을 먼저 답하고, 남은 질문을 한 문장으로 적는다.

## 비교 시험 보고서

여러 조건의 결과를 표로 요청하면 대상·프로토콜·관측값·접속 결과를 한 행에 묶는다. 구조화된 기록이나 반복 생성할 보고서가 필요한 경우 [PEM 시험 예시](examples/pem-quic.json)의 형식을 사용한다. 필드 정의와 실행법은 [시험 기록 형식](references/case-format.md)을 참고한다. 스킬 디렉터리에서 `node scripts/report.mjs examples/pem-quic.json`을 실행하면 입력을 검사하고 표를 생성한다. 일반 질의는 채팅으로 바로 답한다.

자료 등록을 요청받으면 출처와 읽은 구절을 확인해 `register_excerpt`를 사용한다. 최종 회신의 승인과 저장을 사용자가 요청한 경우에만 `save_approved`를 사용한다. 제공된 예시를 고객 승인 사례로 취급하지 않는다.
